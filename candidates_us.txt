# Candidate universe for shortlist.py --keywords-file
#
# WHAT THIS IS: ~110 product keywords to RANK. It is an input, not a result,
# and not a recommendation. Nothing here has been validated against demand
# data — validating it is what the pipeline is for.
#
# WHY IT IS LONG: the score is min-max normalised across whatever you supply,
# so it is comparative. Ranking 16 candidates tells you which of 16 is best,
# which may still be bad. A universe of ~100 makes "top 10" mean something.
#
# COST BEFORE YOU RUN IT: the trend call is one request per keyword per
# profile. With --profile both that is ~220 requests. The competition call is
# billed per LISTING returned and only fires for keywords that clear the trend
# gate, which is the reason the gate order is what it is. Start with a slice:
#
#     head -30 candidates.txt > slice.txt
#     python3 amazon_selector/shortlist.py --keywords-file slice.txt
#
# PROVENANCE: these are plausible categories drawn from general knowledge of
# what sells on Amazon, chosen to span consumer-only, B2B-only and dual-channel
# products so both profiles have something to work with. Six of them (marked
# [touted]) are categories that seller-research blogs publicised as 2026 growth
# stories -- they are here to be TESTED, not trusted: a widely-published
# "rising category" is by definition one every competitor has already read
# about, and the seasonality and moat gates exist to kill the ones that only
# look like opportunities.
#
# Replace this file with your own candidates. The pipeline is the value.
